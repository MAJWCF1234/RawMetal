# Map format 2

A custom map or campaign override (`.rmc`) is a list of pipe-delimited records between the `CUSTOM_CAMPAIGN_DATA` markers. Version 2 adds named fields, names, overrides, custom properties and prefabs. Nothing that loaded before changes. The record reference is `custom maps/GUIDE.html` (sections 8 and 9), generated by `tools/campaign/make_custom_map_guide.py`; the Campaign Builder reads its record fields and named-field labels from that file.

## Version
- `FORMAT|2` is the first record. Without it a file is version 1 and is read exactly as before: a `key=value` field is then a positional field, and an error says the file needs `FORMAT|2`.
- A build refuses a version newer than it reads (`MapFormatVersion`, src/world/EntityTraits.h) and says so.
- The exporter writes `FORMAT|2` only when a map has named fields, so exports of older content are unchanged.

## Named fields
- Any record may end with `key=value` fields after its positional ones. The run is read from the end; a key is a lower-case letter, then letters, digits, `_`, `.` or `-`, so rows of tiles, titles and labels are never read as keys. A `ROW` never has named fields. Values are percent-encoded like every other text field (`|` is `%7C`).
- Every named field is kept as written, in order, by record key (`AuthoredMapData::recordFields`, `recordFieldKey`: tag, parent record, ordinal). The exporter writes them back after the record's own fields, so **unknown keys survive** an older build's export and the Builder's save.
- Known keys are parsed by `parseEntityTraits` into `EntityTraits`. A bad value for a known key is an error that names it. An unknown key is kept and ignored.
- Named fields on records the exporter writes another way (a `PRIM`, which is written as its `STRUCT` boxes, and a `PREFAB_PLACE`, whose records are written out) are listed in the export's notes.

## Names
- `name=` on any record. Names are unique per map; a duplicate is refused. `AuthoredMapData::entityNames` maps a name to its record kind and index.
- Scripts address a named record's property as `@name.key`, or `@N:name.key` for a record on map N, in `SCRIPT_REQUIRE` and in `SCRIPT_ACTION` `STATE` and `ADD`. A name that is not there is refused.

## Overrides
| Group | Keys | On | Read by |
|---|---|---|---|
| Physics | `mass health breakable density floats friction restitution frozen anchored volume soft material` | CLUTTER, plus chairs a FIXTURE turns loose | `Clutter::mass/material/friction/restitution`, `damageClutter`, `breakClutter`, `refreshPinnedClutter` and the solver's pinned skip (Clutter.cpp), `buoyancy::density/floats`, `containers::isContainer/inner`, `soft::isSoft(const Clutter&)` |
| Look | `tint scale texture emissive` | CLUTTER, FIXTURE (`scale` also CREATURE, ACTOR) | `SoftwareRenderer::lookFace`/`lookedTexture` (Scene3D.cpp) for fixtures and props; `playedMap` for sizes |
| Audio | `impact` | CLUTTER | `Clutter::impactSound` |
| Bodies | `faction ai hp weapon role display` | CREATURE, ACTOR | `spawnCreature` and the summon order loop (`Enemy::ordered`); `playedMap` for actor tracks |
| Fixtures | `solid anchored` | FIXTURE | `playedMap` |

- Authored data stays as written. `playedMap` (EntityTraits.cpp) makes the copy the world plays (sizes, anchoring, a man's side, mind, health and weapon); `World::loadAuthoredMap` loads it. So a size factor is never applied twice, and the exporter and the Builder write back what the author wrote.
- The words for sides, orders, weapons and roles are the console summon's (`parseFactionWord`, `parseOrderWord`, `parseWeaponWord`, `parseRoleWord`). `Summon.cpp` uses the same parsers, so an authored body can have any trait a summon can.
- Prop and creature overrides are not saved. On load, the save reconcile takes them from the authored prop or spawn it matches (`Enemy::adoptTraits`, `Clutter::traits`).

## Custom properties
- `p.key=value` on a record. Scripts see a whole number: text reads 0, and true or yes reads 1.
- A named prop's `frozen` is a property too. A script lets the prop go with `STATE @name.frozen 0`.
- Scripts reach a property as `@name.key`, so it needs a `name=`. A record without one still keeps its properties, under its id key (`#prop:3` for CLUTTER record 3, `Game::entityIdKey`).
- The parser resolves each property to a StateId (`entityPropertyState`: map index, map name, entity, key). That is only an identifier. `AuthoredMapData::propertySeeds` files the authored values and the properties scripts name.
- All runtime access goes through src/game/EntityProperties.cpp: `seedEntityProperties`, `isEntityProperty`, `entityPropertyInt` and `setEntityPropertyInt`.
  - The authored value is the map's.
  - What scripts change goes to the save's entity store: `Game::setEntityProperty(map, entity, "p.key", value)` (`"frozen"` for the flag).
  - A read takes the store's value when there is one, else the authored value.
  - The store is saved in the `entities` section (save format 28, docs/Systems/save-format.md) and emptied by a new game. A format 27 save still loads; it has no store, so the authored values stand.
  - No script state is written for a property.

## Floors: finishes, flooring and footings
| Keys | On | What |
|---|---|---|
| `tread riser stringer` | STAIR | Step tops (a 4 cm walking face), step fronts and bodies, side rails. Structure materials (`finishMaterialAllowed`, World.h). |
| `deck edge railing` | LAYER | The storey's balconies (`=` tiles): walking face, edge and underside, railings. |
| `trim trimwidth` | STRUCT | A flooring's edge band (0.1 m if no width). |
| `drape` | STRUCT on the land | `1`: the flooring follows the ground (a path): drawn over the land's own triangles cut to its box, not solid. |
| `footing snap raise base cap capwidth steps terrace` | STRUCT | A room or floor on the land, or raised: src/world/Footing.h. |

- Faces and bands are split off once a map is built and grounded (`World::splitFinishes`), so on terrain a step top, a deck face and a trim band keep the one height grounding gave the whole. New pieces are appended; record indices do not move.
- **Footings** (`Footing.h`, shared by the engine and the Builder). The box is the footprint. `snap` (low, mean, high; fixed: the bottom field is the height) measures the land under it before any footing cut it; `planFooting` gives its level pieces (a stepped footing is terraces along its long side). The parser adds each footing's pad to the campaign's `TerrainShape` (`footingPads`: level for pad and stepped, cut-only for foundation and stilts); `terrainColumnDensity` puts the ground of a pad's columns at its exact height to the 32nd of a metre, so Surface Nets and collision walk it there. `World::buildFootings` lays the slab (the record's material, the `cap` ring split off as a trim), a plinth of `base` down to the land or the floor below, posts for stilts, steps between terraces, and steps from any door on a raised edge to the ground outside (`steps=0` leaves them off).
- Inside a footing, `World::floorHeight` is its floor: walls stand on it and rise from it, and grounding (`settleExclusionFacilityOnTerrain`) stands what is inside (floor paint, stairs, storeys, furniture) on it. Footing pieces keep their heights (`Structure::fixedHeight`).
- On the land a wall face reaches down to the lowest ground along it (Scene3D), so a face on a slope leaves no daylight under its low end.

## Material turns
Planks, tiles, brick courses, tread plate and grating have a direction. A turn says which way they run, in degrees (0 to 360; a quarter turn is 90). Absent, or 0 or 360, the texture runs as it always has.

| Key | On | Turns |
|---|---|---|
| `turn` | STRUCT, PRIM | The record's material on every face of it (a shape: on every box it lays). |
| `treadturn` | STAIR | The step tops (with `tread=`, the 4 cm walking face; without, the whole step). |
| `deckturn` | LAYER | The storey's balcony floors (with a split deck, the walking face). |
| `wallturn floorturn ceilingturn` | SURFACE | The map's wall finish (above a painted dado band, the paint), floor finish (the walking face) and ceiling finish. |

- The parser (`turnField`, CustomCampaign.cpp) refuses a value that is not degrees or lies outside -360 to 360, naming the key, and keeps the rest in [0, 360) (`Structure::turn`, `topTurn` for a walking face split off by `World::splitFinishes`; `Staircase::treadTurn`; `MapLayer::deckTurn`; `AuthoredMapData::wallTurn floorTurn ceilingTurn`). An edge trim, a footing's base and cap keep their own way.
- The renderer turns the texture about its origin on each face, in metres, so a tile keeps its size and shape (Scene3D `setTurn`: `emitQuad`, `emitQuadPiece` and the shapes' triangles). The GPU and software paths draw the same faces, and the game and the Builder's 3D view the same engine. No turn leaves the coordinates untouched: an older map draws exactly as before.
- The exporter writes the turns back with the record's other named fields; a PRIM whose boxes still carry its turn goes back as the PRIM.
- The Builder: the Paint tool lays its paint turned (R a quarter, Shift+R back; a stroke just painted turns with it), and so do the Floor and Flooring tools; the Turn box on the right turns a picked block, shape, stair or storey (any angle under Advanced).
- Tests: `--each-test=map-format` (parse, refuse, export and load back), the lab tube `material-turn` (a plank floor turned a quarter runs the other way, GPU and `--software`), the Builder's `--turn-test`. The Starter Map's Hillside house has its planks turned (`turn=90`).

## Prefabs
- `PREFAB|name` ... `PREFAB_END` holds records in metres from the prefab's origin, with `@` in their map field. A prefab must be defined above its first `PREFAB_PLACE`.
- `PREFAB_PLACE|map|prefab|x|y|z|yaw[|prefix]` sets the prefab down:
  - points move and turn with it;
  - yaws turn with it (subtracted for `SIGN` and `TERMINAL`, which face (sin, cos));
  - heights rise by `z`;
  - boxes and quarter facings (`STRUCT`, `PRIM`, `HAZARD`, `WATER`...) turn only by quarter turns;
  - `prefix` goes before every `name=` inside.
- Records that name others by number (`ACTOR*`, `LEAD`, `CHAIN`, `JOINT`, `BREAKABLE`, `SCRIPT_*`, `DIALOGUE*`, `TIMED_SEQUENCE`, a `LIGHT` riding a prop) cannot go in a prefab.
- The exporter writes the placed records (a flat map). The Builder keeps the blocks as written.

## Campaign Builder
- `NativeDocument::fields` gives a record's positional fields, so every tool that edits a field by number works as before.
  - `replace` keeps the line's named fields.
  - `named`, `replaceNamed` and `withNamed` read and write them.
  - Copies keep their overrides but not their name.
- The index leaves `FORMAT` and `PREFAB` blocks out of every map.
- The inspector lists the named fields under the record's own, labelled from the guide's `data-named` rows.
  - The last row adds a field (`key=value`), and an emptied row removes one.
  - Adding the first named field puts in `FORMAT|2`.
- **Make prefab** turns the picked things into a block and one placement. **Place prefab** adds another placement with its own name prefix. Each is one Ctrl+Z.

## Openings: window walls
`GLAZING|map|x1|y1|x2|y2|bottom|top` is a new record, with its options as named fields (`cols spacing rows sill head frame depth look door door_head pane panes infill cut wall health`; the guide's section 8 and 9 list them).
- `AuthoredMapData::glazings` keeps the record as written. The exporter writes it back the same way.
- `playedMap` calls `applyOpenings` (src/world/Openings.cpp) on the copy the world plays. It:
  - cuts the wall's `#` tiles and wall `STRUCT` boxes from sill to head;
  - builds the cut tiles back below the sill and above the head;
  - adds the frame as `STRUCT` boxes;
  - adds every glass pane as a `BREAKABLE` after the map's own.
- Mesh panes are `STRUCT` material 52 (`ChainLinkMaterial`). Like glass, `seeThroughMaterial` lets light, sight and rounds through it; unlike glass, it never breaks.
- `BREAKABLE` takes `glaze=` (clear dirty tinted frosted wired) and `cracked=` (0-8 star cracks it starts with). Pre-cracks are ordinary pane hits, so the `world` section of the save keeps them with the rest.
- The lab tube `storefront` (src/lab/tubes/Storefront.cpp) checks:
  - the cut;
  - each pane breaking alone;
  - the mesh;
  - the doorway;
  - a save and load;
  - walls never hurt (every pane down, every other box and tile as it was);
  - the frame looks, a grid-wide `pane=` and an empty pane.
- The Builder's Window wall tool writes the record from the tool's boxes. A click on a bay of a storefront gives every pane in it the kind picked in Panes (Shift: the bottom pane only) by rewriting its `panes=` letters, one Undo. The document's tiles never change: the cut, and putting the wall back when the record goes, are the engine's.

## Openings: breaches
`BREACH|map|x1|y1|x2|y2|bottom|top` is a hole broken through a wall, its options as named fields (`shape edge sill head rebar rubble seed toward infill wall`).
- `AuthoredMapData::breaches` keeps the record; the exporter writes it back the same way.
- `applyOpenings` cuts it after the glazings, with the same cut (`cutWall`): the hole's outline as boxes (one for `rect`, slices of a half circle for `arch`, ragged strips for `ragged`), the wall's tiles and wall boxes cut to it, the rest of the cut tiles built back round it.
- The cut is strips 4-10 cm wide; their wall pieces stay as invisible collision proxies, and are drawn as engine-only shapes (`ShapeLip`, `ShapeFoot`) whose edge slopes from one outline corner to the next, so the hole reads as one broken line, not steps.
- The broken edge is non-solid chunks of core (`ShapeShard`: a box with each corner pulled in at random, concrete 15 or brick 31), rebar ends on the slant (`ShapeRod`, material 8), and rubble `FIXTURE`s, all from `seed`, so a map plays the same every time.
- The hole is a real gap: the player, the creatures' walk test (`aiWalkSegment`) and their node graph, rounds and the light-occlusion ray (`World::lightRayHit`, which the probes and shadows use) all go through it.
- The lab tube `breach` (src/lab/tubes/Breach.cpp) checks the cut, the edge, a walk through, the creatures' walk and route, rounds and the lamp's light through it, and a save.
- The Builder's Breach tool writes it from a drag along a wall (# tiles or a wall `STRUCT`) and refuses one on open floor.

## Growth
The Builder's Growth brush paints ordinary `FIXTURE` records (solid 0), so nothing in the format is new:
- ivy (`ivy_wall_a`, `ivy_wall_b`, `growth_vine_sheet`) and wall moss (`growth_moss_wall`) flat on a wall's face, a centimetre off it, `yaw` turning their face out;
- drapes of ivy (`growth_ivy_curtain`: seven strands of uneven length side by side; `growth_ivy_single`: one strand) hanging 0.5-3 m down a wall from the ceiling's edge or over a ledge's lip, flat on the face, their base their length below the lip (never from mid-air);
- grass (the Nature brush's tufts) and `growth_moss_floor` on a floor or a ledge's top.
- Creepers are hanging plants (`SoftwareRenderer::hangingPlant`, `PlantBones::add(..., hanging)`): rooted at their top, they drift in an indoor draft and part round whoever walks through them. The lab tube `growth` (src/lab/tubes/Growth.cpp) checks it.
- The brush's density, size and seed are its own settings, not map data; a typed seed repeats a stroke exactly.

## Joints
`JOINT|map|kind|propA|propB|x|y|z[|x2|y2|z2]` joins a loose prop to another, or to the room (World.h `PropJoint`, parsed in
CustomCampaign.cpp, written back by CampaignExport.cpp; physics.md has how they play).
- `propA` and `propB` are CLUTTER records of the map counted from 0; `propB -1` is the room (a wall, the ceiling, the floor).
- `kind`: `hinge ball slider weld rope chain spring rod pulley winch` (`distance` reads as `rod`). x,y,z is where they meet
  (absolute heights). A rope, chain, spring, rod, pulley or winch needs its other end x2|y2|z2 (on propB, or the point in the
  room it hangs from); a pulley joins two props.
- The pose its props are laid out in is the joint's rest.
- Named fields (all optional): `axis` (x, y, z or a,b,c; a hinge x, a slider z), `length`, `min` and `max` (degrees for a
  hinge, metres for a slider or a winch), `cone`, `cone2`, `twist` (a ball's, degrees), `stiffness` (Hz) and `damping`,
  `motor` (speed servo off) with `speed`, `force`, `target`, `switch` (a state the motor runs on), `breaks` (N), `state` (set
  when it snaps), `over` and `over2` (a pulley's wheels), `ratio`, `radius` (how thick it is drawn), `friction` (a hinge's
  or ball's N m, a slider's N: held still until pushed harder, so a nudged door stops where it is left), `detent` (where a
  hinge or slider catches: up to four, degrees or metres from its rest, `a,b`), `catch` (how near a detent it is pulled
  there: 8 degrees or 2.5 cm by default) and `latch` (the most a detent holds with, N m or N; 0 the detent's spring alone).
  `detent` is for a hinge or slider only, `friction` for a hinge, slider or ball. A nailed board is a `weld` (or a `ball`,
  one nail) with `breaks`.
- The Builder's Connect tool writes it, with defaults by kind: a door (an upright hinge) `friction=2 detent=0 latch=8`, a
  hatch `friction=2 detent=0 latch=15`, a seesaw `friction=.5`; Drawer a slider along the side the drag pulls it out by,
  `min=0`, `max` three quarters of its length, `friction=4 detent=0 latch=12`; Nailed a weld with `breaks=600`. Deleting a CLUTTER record in the Builder takes the joints on it with it and renumbers
  the rest; a LIGHT riding it stays, riding nothing.
- A map without JOINT records is unchanged. The tube `joints-room` plays the Starter Map's.

## Cloth
`CLOTH|map|kind|x|y|z[|x2|y2|z2]` hangs a curtain, a strap or a cable (World.h `ClothSpec`, parsed in CustomCampaign.cpp,
written back by CampaignExport.cpp; physics.md has how they play). Heights are absolute.
- `kind`: `curtain` hangs from a rail from x,y,z to x2,y2,z2 (its top edge); `strap` hangs from x,y,z (x2,y2,z2, if given,
  is the way its face turns across); `cable` hangs from x,y,z to x2,y2,z2, sagging by its spare length. A curtain and a cable
  need x2|y2|z2; a curtain's rail is at least 0.2 m long.
- Named fields (all optional): `drop` (how far a curtain hangs, 0.1-8 m; 1.6), `length` (a strap's, 1 m; a cable's, 1.15
  times the span between its ends; 0.1-20 m), `width` (a strap's, 0.01-0.5 m; 0.05), `radius` (a cable's thickness,
  0.003-0.1 m; 0.012), `mass` (kg in all; a curtain 0.35 kg a square metre, a strap 0.25 kg, a cable 0.4 kg a metre),
  `stiffness` (how firmly its links hold, 1-120 Hz; 30), `loose=1` (a cable's far end lies free toward x2,y2,z2).
- The Builder's Hang cloth tool (Decor) writes it: a curtain dragged along where its top hangs (from the ceiling to just over
  the floor, or a shorter drop picked), a strap clicked where it hangs from, a cable dragged from end to end, a loose cable
  from where it leaves the wall to where its end lies.
- A map without CLOTH records is unchanged. The Starter Map's SHOWCASE: PHYSICS has a curtain on a frame, a strap and a loose
  cable over a crate (make_starter_map.py `cloth_corner`); the tube `cloth-room` plays them.

## Light shafts
`STRUCT` material 53 (`LightShaftMaterial`) is a god ray: sunlight falling on the slant through its box, in at the top on the side away from its `facing` (field 12) and down to the floor on the facing side.
- It is drawn as soft additive cards, warm gold, so it shows without any haze; it casts no shadow. Its light is shaped by the world it falls in (`lightShaftShape`, Scene3D.cpp): over the box's far face a grid finds where the light comes through (the breach's hole, the glass, not the wall or the frame round them) and where each ray lands (the floor, or the first thing in its way). The cards run from the opening's outline to where the light is caught, so a shaft never reaches past a wall or into the room behind.
- Drawn every frame after the room: hidden by what stands in front of it, faded where it nears a surface behind it (a soft-particle depth fade, so no hard line where it meets the floor or a wall) and as a card turns edge-on to the eye. Where it lands, a soft warm patch on the floor: the opening cast on it, the window bars' shadows in it. The lab knobs `shaft.layer`, `shaft.sheet`, `shaft.pool`, `shaft.soft` and `shaft.colour` tune it.
- It is never solid (the parser makes it so), and like glass it lets light, sight and rounds through (`seeThroughMaterial`).
- The Builder's Block tool places one: pick material 53 and drag its box; R turns its facing once the record has one (the inspector lists `facing`). The lab tube `atrium` checks the Starter Map's five.

## Shapes (PRIM)
`PRIM|map|kind|x|y|z|w|d|h|facing|material[|solid]` lays a ready-made building part. The kinds, their plain names, palette groups, player-scaled defaults and plan outlines are one table, `src/world/PrimitiveKinds.h`, read by the engine (`Primitives.cpp`), the Campaign Builder's Shape tool and the guide generator.
- Ten new kinds: `wedge` (gable roof), `cone` (spire), `pyramid` (hip roof), `spiral` (spiral stair), `culvert` (a round pipe sunk into the floor), `buttress`, `chamfer` (bevelled block), `octagon` (eight-sided pillar), `arcwall` (curved wall) and `catwalk`. They draw true to their shape (STRUCT shapes 12-20) over collision boxes; the spiral stair, culvert and catwalk are walked, the steep ones are not (`--each-test=primitives`).
- Options as named fields: `hand=left|right` (spiral), `rails=both|left|right|none` (catwalk), `thick=` metres (arcwall, culvert).
- A PRIM is kept as a record (`AuthoredMapData::primitives`, the boxes it laid): the exporter writes it back as the PRIM it was, its named fields with it. One whose boxes were changed after it was laid is written as its boxes.
- Where solids overlap, the renderer leaves out faces buried inside another and draws flush faces once (the later record's): `src/renderer/ShapeCulling.h`, done when the map's geometry is built; collision is untouched. The lab tube `culling` checks it.

`Showcase Atrium` (map 149; south of Predator, tools/campaign/make_starter_map.py `atrium`) and `Showcase Shapes` (map 60, built last on the forest's map in its cell, as the Hillside is, so no other map's number moves: every shape, the ten new ones at full size, a building of overlapping prims) are found by name in lab fixtures (`map-name`). ## Underground (CAVE)
`CAVE|op|x1|y1|z1|x2|y2|z2|radius[|rough[|strength]]` is campaign-wide, in world metres like `TERRAIN_SCULPT` (src/world/CaveField.h).
- The terrain is a density field that Surface Nets skins (World::buildTerrain) and the collision walks (`terrainSurfaceBelow`/`Above`, `fits`). A cave is a change to that field, so the walls, roof, floor, collision and the mouth where a tunnel breaks the hillside all come from the same samples.
- `carve` digs a rough tube round the line, its floor flat 0.6 radius under it (a point: a cavern); `fill` puts rock back; `move` pulls the field round point 1 to point 2 over `radius` (the Move brush); `smooth` evens it; `flatten` levels a floor at z1. `rough` (0.35) noises the walls, `strength` (1) scales move, smooth and flatten.
- `buildCaveVolume` works the strokes out once, after the flats, the footings' pads and the sculpts, over world-metre samples covering their boxes (`TerrainShape::caveVolume`); every chunk and the Campaign Builder sample the same field. The bottom two sample rows (-13, -12) are never carved, so the field always closes under the deepest floor.
- Changed samples are `TerrainCave`: drawn with the mine pack's rock (`mine_tunnel_straight_rocks_w`) on walls and roofs and its rough soil on floors.
- `cave=1` on a FIXTURE, CLUTTER, CREATURE, PICKUP or LIGHT measures it from the floor of the cave under it (`World::caveFloor`), not the land's top. WATER heights are absolute, so a pool in a cave is an ordinary WATER record.
- Under a carved roof (`World::underRock`) the game is dark (`Game::darknessTarget`): the sky's ambient goes, lamps, lanterns and the torch still light.
- The exporter writes the records back as read; `sameTerrainOver` compares the strokes that reach a map, so the Builder's live picture rebuilds only the maps a stroke reached. Old maps have no CAVE records and load as before; saves are unaffected.
- The Builder's **Cave** tool writes them: dig (brush a tunnel at the depth picked, click a cavern), cave mouth (drag in from the hillside), fill back, move the wall, smooth, flatten the floor. The Terrain tool's **Move** brush drags the land after the pointer (Shift lifts it). `--cave-test` (NativeCaveRegression.inc; `--editing-test` runs it too) drives both. The lab tube `caves` (src/lab/tubes/Caves.cpp, lab/fixtures/caves.rmc) checks the carving renders, no holes, a walk in, the rock holding, `cave=1`, darkness and an export round trip.
