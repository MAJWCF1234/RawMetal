# Map format 2

A custom map or campaign override (`.rmc`) is a list of pipe-delimited records between the `CUSTOM_CAMPAIGN_DATA` markers. Version 2 adds named fields, names, overrides, custom properties and prefabs. Nothing that loaded before changes. The record reference is `custom maps/GUIDE.html` (sections 8 and 9), generated by `tools/campaign/make_custom_map_guide.py`; the Campaign Builder reads its record fields and named-field labels from that file.

## Version
- `FORMAT|2` is the first record. Without it a file is version 1 and is read exactly as before: a `key=value` field is then a positional field, and an error says the file needs `FORMAT|2`.
- A build refuses a version newer than it reads (`MapFormatVersion`, src/world/EntityTraits.h) and says so.
- The exporter writes `FORMAT|2` only when a map has named fields, so exports of older content are unchanged.

## Named fields
- Any record may end with `key=value` fields after its positional ones. The run is read from the end; a key is a lower-case letter, then letters, digits, `_`, `.` or `-`, so rows of tiles, titles and labels are never read as keys. A `ROW` never has named fields. Values are percent-encoded like every other text field (`|` is `%7C`).
- Every named field is kept as written, in order, by record key (`AuthoredMapData::recordFields`, `recordFieldKey`: tag, parent record, ordinal). The exporter writes them back after the record's own fields, so **unknown keys survive** an older build's export and the Builder's save.
- Known keys are parsed by `parseEntityTraits` into `EntityTraits`. A bad value for a known key is an error that names it. An unknown key is kept and ignored.
- Named fields on records the exporter writes another way (a `PRIM`, which is written as its `STRUCT` boxes, and a `PREFAB_PLACE`, whose records are written out) are listed in the export's notes.

## Names
- `name=` on any record. Names are unique per map; a duplicate is refused. `AuthoredMapData::entityNames` maps a name to its record kind and index.
- Scripts address a named record's property as `@name.key`, or `@N:name.key` for a record on map N, in `SCRIPT_REQUIRE` and in `SCRIPT_ACTION` `STATE` and `ADD`. A name that is not there is refused.

## Overrides
| Group | Keys | On | Read by |
|---|---|---|---|
| Physics | `mass health breakable density floats friction restitution frozen anchored volume soft material` | CLUTTER, plus chairs a FIXTURE turns loose | `Clutter::mass/material/friction/restitution`, `damageClutter`, `breakClutter`, `refreshPinnedClutter` and the solver's pinned skip (Clutter.cpp), `buoyancy::density/floats`, `containers::isContainer/inner`, `soft::isSoft(const Clutter&)` |
| Look | `tint scale texture emissive` | CLUTTER, FIXTURE (`scale` also CREATURE, ACTOR) | `SoftwareRenderer::lookFace`/`lookedTexture` (Scene3D.cpp) for fixtures and props; `playedMap` for sizes |
| Audio | `impact` | CLUTTER | `Clutter::impactSound` |
| Bodies | `faction ai hp weapon role display` | CREATURE, ACTOR | `spawnCreature` and the summon order loop (`Enemy::ordered`); `playedMap` for actor tracks |
| Fixtures | `solid anchored` | FIXTURE | `playedMap` |

- Authored data stays as written. `playedMap` (EntityTraits.cpp) makes the copy the world plays (sizes, anchoring, a man's side, mind, health and weapon); `World::loadAuthoredMap` loads it. So a size factor is never applied twice, and the exporter and the Builder write back what the author wrote.
- The words for sides, orders, weapons and roles are the console summon's (`parseFactionWord`, `parseOrderWord`, `parseWeaponWord`, `parseRoleWord`). `Summon.cpp` uses the same parsers, so an authored body can have any trait a summon can.
- Prop and creature overrides are not saved. On load, the save reconcile takes them from the authored prop or spawn it matches (`Enemy::adoptTraits`, `Clutter::traits`).

## Custom properties
- `p.key=value` on a record. Scripts see a whole number: text reads 0, and true or yes reads 1.
- A named prop's `frozen` is a property too. A script lets the prop go with `STATE @name.frozen 0`.
- Scripts reach a property as `@name.key`, so it needs a `name=`. A record without one still keeps its properties, under its id key (`#prop:3` for CLUTTER record 3, `Game::entityIdKey`).
- The parser resolves each property to a StateId (`entityPropertyState`: map index, map name, entity, key). That is only an identifier. `AuthoredMapData::propertySeeds` files the authored values and the properties scripts name.
- All runtime access goes through src/game/EntityProperties.cpp: `seedEntityProperties`, `isEntityProperty`, `entityPropertyInt` and `setEntityPropertyInt`.
  - The authored value is the map's.
  - What scripts change goes to the save's entity store: `Game::setEntityProperty(map, entity, "p.key", value)` (`"frozen"` for the flag).
  - A read takes the store's value when there is one, else the authored value.
  - The store is saved in the `entities` section (save format 28, docs/Systems/save-format.md) and emptied by a new game. A format 27 save still loads; it has no store, so the authored values stand.
  - No script state is written for a property.

## Floors: finishes, flooring and footings
| Keys | On | What |
|---|---|---|
| `tread riser stringer` | STAIR | Step tops (a 4 cm walking face), step fronts and bodies, side rails. Structure materials (`finishMaterialAllowed`, World.h). |
| `deck edge railing` | LAYER | The storey's balconies (`=` tiles): walking face, edge and underside, railings. |
| `trim trimwidth` | STRUCT | A flooring's edge band (0.1 m if no width). |
| `drape` | STRUCT on the land | `1`: the flooring follows the ground (a path): drawn over the land's own triangles cut to its box, not solid. |
| `footing snap raise base cap capwidth steps terrace` | STRUCT | A room or floor on the land, or raised: src/world/Footing.h. |

- Faces and bands are split off once a map is built and grounded (`World::splitFinishes`), so on terrain a step top, a deck face and a trim band keep the one height grounding gave the whole. New pieces are appended; record indices do not move.
- **Footings** (`Footing.h`, shared by the engine and the Builder). The box is the footprint. `snap` (low, mean, high; fixed: the bottom field is the height) measures the land under it before any footing cut it; `planFooting` gives its level pieces (a stepped footing is terraces along its long side). The parser adds each footing's pad to the campaign's `TerrainShape` (`footingPads`: level for pad and stepped, cut-only for foundation and stilts); `terrainColumnDensity` puts the ground of a pad's columns at its exact height to the 32nd of a metre, so Surface Nets and collision walk it there. `World::buildFootings` lays the slab (the record's material, the `cap` ring split off as a trim), a plinth of `base` down to the land or the floor below, posts for stilts, steps between terraces, and steps from any door on a raised edge to the ground outside (`steps=0` leaves them off).
- Inside a footing, `World::floorHeight` is its floor: walls stand on it and rise from it, and grounding (`settleExclusionFacilityOnTerrain`) stands what is inside (floor paint, stairs, storeys, furniture) on it. Footing pieces keep their heights (`Structure::fixedHeight`).
- On the land a wall face reaches down to the lowest ground along it (Scene3D), so a face on a slope leaves no daylight under its low end.

## Prefabs
- `PREFAB|name` ... `PREFAB_END` holds records in metres from the prefab's origin, with `@` in their map field. A prefab must be defined above its first `PREFAB_PLACE`.
- `PREFAB_PLACE|map|prefab|x|y|z|yaw[|prefix]` sets the prefab down:
  - points move and turn with it;
  - yaws turn with it (subtracted for `SIGN` and `TERMINAL`, which face (sin, cos));
  - heights rise by `z`;
  - boxes and quarter facings (`STRUCT`, `PRIM`, `HAZARD`, `WATER`...) turn only by quarter turns;
  - `prefix` goes before every `name=` inside.
- Records that name others by number (`ACTOR*`, `LEAD`, `CHAIN`, `BREAKABLE`, `SCRIPT_*`, `DIALOGUE*`, `TIMED_SEQUENCE`, a `LIGHT` riding a prop) cannot go in a prefab.
- The exporter writes the placed records (a flat map). The Builder keeps the blocks as written.

## Campaign Builder
- `NativeDocument::fields` gives a record's positional fields, so every tool that edits a field by number works as before.
  - `replace` keeps the line's named fields.
  - `named`, `replaceNamed` and `withNamed` read and write them.
  - Copies keep their overrides but not their name.
- The index leaves `FORMAT` and `PREFAB` blocks out of every map.
- The inspector lists the named fields under the record's own, labelled from the guide's `data-named` rows.
  - The last row adds a field (`key=value`), and an emptied row removes one.
  - Adding the first named field puts in `FORMAT|2`.
- **Make prefab** turns the picked things into a block and one placement. **Place prefab** adds another placement with its own name prefix. Each is one Ctrl+Z.
